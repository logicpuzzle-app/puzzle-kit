# ジャンル・検査設定のネイティブ保存

公開File Openでジャンルが復元されずCheck Answerが表示されない、保存後に無効化した検査が
元へ戻る、別盤面の設定を引き継ぐ問題を防ぐ。盤面と設定を一緒に保存・復元する。
セル・頂点・辺のID、グラフ、注記の参照には変更を加えない。

## 保存内容と適用

`PuzzleExport.constraintSettings` は任意の `PuzzleConstraintSettings` とする。

| フィールド | 内容・欠落時の値 |
| --- | --- |
| `currentSchemaId` | ジャンルの正確な文字列。未選択はnull |
| `currentInputMode` | 入力モード。欠落時auto |
| `validationOverrides` | 検査IDから有効／無効への対応。欠落時空 |
| `highlightOverrides` | 強調表示IDから有効／無効への対応。欠落時空 |
| `showConstraintLayer` | 制約モードの有効状態。旧4フィールド形式ではジャンル指定ありならtrue |
| `savedInputModes` | 問題／解答の入力モード。旧形式では両方currentInputModeから初期化 |

設定のない旧ファイルはジャンル未選択・auto・上書きなしに戻す。前の盤面の設定は流用しない。
読込時にプリセット選択操作を呼ばないため、ジャンルの既定の枠・格子を再適用して保存形状を変えない。
問題／解答レイヤーでは入力ツールも反映し、他レイヤーでは切替時に保存モードを適用する。
独立して保存されたユーザー設定は、起動時に先に復元されたネイティブ盤面を上書きしない。
初期化effectの再実行で共有URLが消えた後に古い自動保存を読まない。設定パネルも初期化時に入力モードをautoへ戻さない。
直前の正誤結果・正解メッセージは引き継がない。Newも検査／強調表示の上書きを初期化する。

ジャンルID・検査IDはtrim・正規化しない。未知の文字列を別ジャンルへ置き換えたり捨てたりしない。
カタログはprototypeを持たない辞書を使い、未登録の `toString` 等を登録済みジャンルと誤認しない。
未登録ジャンルの判定は正解にならず、既存APIと同じnullを返す。任意の外部ジャンルの検査を実装するものではない。

設定オブジェクト、ジャンルID、入力モード、booleanの上書き、表示状態を盤面への適用前に検証する。
不正な型・未対応入力モードは読込失敗とし、現在の盤面・設定・Undo履歴を保持する。
読み込んだ設定は複製してストアへ渡し、元ファイルのオブジェクトと共有しない。
Undo/Redoは従来どおり盤面の編集履歴を扱い、ファイル読込は新しい編集セッションを開始する。
検査設定変更自体を盤面Undoの対象に追加する変更ではない。

## 対応する入出力

- メニューとアイコンのFile Open/Save、ストアimport/export。
- アイコンの埋込み共有URLと公開URLローダー。
- メニューの共有ストレージへの送信と `?id=` による読込。
- Masterの自動保存と再読込。設定だけの変更も保存を予約する。
- PersistenceManagerを使うhookの自動保存・保存スロット・JSON保存復元。
- ローカル一覧保存API、JSON出力API、ImportExportDialogのJSON出力。

`serializePuzzle`・`generateShareUrl`・`autoSave`・`savePuzzleToList`・`exportToJson` は末尾に任意の設定引数を追加する。
`downloadAsJson` は既存の第5引数filenameを保ち、第6引数へ設定を追加する。
既存の呼出しは有効で、設定引数を渡さない低レベルAPIがストアから暗黙に設定を取得することはない。
保存済みの旧4フィールド形式も受理し、ファイルバージョンは1.7の任意フィールド追加として扱う。

penpa-edit/puzz.link等の外部形式へ独自の検査設定を埋め込む変更ではない。
ImportExportDialogは現行Masterに常設されていない公開コンポーネントで、JSON出力APIの検証と型チェックを行う。
共有ストレージの検証は実際の送受信ハンドラーにメモリ内アダプターを接続する。外部Firebaseへの書込みは行わない。

## 回帰確認

任意IDを持つ固定ぬりみさき盤面を公開File Openから読み、プリセットの選び直しなしで正解判定する。
Shadeだけを変更して自動保存を待ち、再読込で入力モードを保持する。
数字99と視線検査無効のファイルをアイコンから開き、保存したルール設定に従って正解になることを確認する。
メニューとアイコンの保存ファイル、共有URL読込で設定・盤面参照を比較する。
検査を再び有効にしたファイルは誤答、設定のないファイルはジャンル未選択になる。

共有URLのE2EはOSクリップボードへの書込みだけを捕捉し、実際に生成されたURLへ移動して復元する。
アプリの盤面・設定を直接注入しない。画像・動画はPlaywright + Chromiumで記録する。
Unitでは不正設定の原子的拒否、未知ジャンル、旧形式、ストレージアダプター、保存スロットと自動保存も検証する。
