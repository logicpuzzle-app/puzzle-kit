# パズル制約・エディタ拡張 設計メモ (puzzle-kit)

目的: パズルごとの制約/ツール/検証をデータ化し、エディタ・プレイヤー・ソルバーを組み立てられる仕組みを作る。

## 基本方針
- Penpa互換シリアライズを維持しつつ、拡張メタデータとして制約/ツールプリセットを保存する。
- 制約をスキーマとして定義し、UI生成と検証ロジックのマッピングを分離する。
- パズル定義（種別カタログ）に、グリッド種別/制約セット/使用ツール/検証フック/シリアライズ拡張キーをまとめる。

## 制約スキーマのプリミティブ例
- スコープ: cell / edge / vertex / region / line / object
- ルール型:
  - 値比較: eq/neq/range/allDifferent/oneOf
  - 数量: sum/count/atMost/atLeast/exactly
  - 連結性: regionConnectivity / pathLoop / no2x2 / noBranch / noCycle
  - 幾何: orthogonal adjacency, diagonal禁止/許可、接続数制約
  - セット: contains/excludes（例: セル内に数字/シンボルが存在）
  - 領域: クラスタ（色/線/壁）による分割と面積指定
- パラメータ: 定数/ユーザー入力/盤面要素参照（例: 盤面の数字をnとして sum==n）

## UI生成方針
- パズル定義で「有効ツールセット（モード/サブモード/アイコン）」を指定し、Ribbon/パネルをプリセット。
- 制約パネル: スキーマからフォームを生成（数値入力、選択、範囲指定、シンボル選択など）。
- 盤面操作との紐付け: 制約がセル/辺/頂点を指す場合、クリックで座標リストを取得し制約にバインドする。

## 検証ロジック
- 制約→評価関数のマッピングをプラグイン化（関数シグネチャ: (state, grid, constraint) => result）。
- 汎用制約はライブラリ化（sum/count/allDifferent/connectivityなど）。パズル固有は個別実装。
- ソルバーまではスコープ外とし、まずはバリデータ（検証）を優先。

## シリアライズ拡張
- Penpa互換JSONに拡張フィールド `ext.constraints`, `ext.tools`, `ext.puzzleType` などを追加。互換プレイヤーは `ext` を無視できる設計。
- import/export と回帰テストを追加（既存リンクに影響がないことを確認）。

## 初期対応パズル（例）
- Slitherlink/Loop系: 線の連続・分岐なし・数字周囲本数。
- Sudoku系: allDifferent + 追加制約（サム/矢印/サーモ等）。
- Kakuro: 行列ごとのsum、重複禁止。
- Nurikabe/Heyawake: 黒領域連結・2x2禁止・部屋制約。
- Fillomino/Region系: 同数字領域・サイズ一致・境界線。

## 全パズル移植に向けた考慮点・特殊ケース
- グリッド種別: hex/tri/pyramidなど非正方形での座標・隣接判定。
- 複合入力: ケージ自動生成、マルチカラー、矢印/サーモ/多点オブジェクト。
- 描画と判定の乖離: 見た目の線/壁と論理グラフの辺が一致しない場合の扱い。
- 解答マスク/領域: Solution area の扱いと判定対象範囲。
- シンボル前面/背面: 線や塗りと重ね順が違う場合の判定。
- 互換性: 既存Penpaリンクに ext データがない場合でも正常動作するフォールバック。
- パフォーマンス: 大規模盤面の検証（連結性/経路探索）の効率。
- 多言語: 制約やツール名のi18n辞書。

## 実装ステップ案
1) 制約スキーマ型と評価インターフェイスを定義。共通制約関数を実装。
2) パズル定義カタログを作成（ツールプリセット＋制約セット＋グリッド種別）。
3) 制約パネルのフォーム生成（スキーマ→UI）、選択された盤面座標とのバインド。
4) 検証ルーチンをエディタ/プレイヤーに組み込み、結果表示（エラー箇所ハイライト）。
5) シリアライズ拡張 `ext` を追加し、回帰テストでPenpa互換を確認。
6) パズル種別を順次拡充し、特殊ケース（非正方形グリッド、複合オブジェクト）に対応。
