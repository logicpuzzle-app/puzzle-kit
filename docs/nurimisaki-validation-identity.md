# ぬりみさき判定と盤面ID

IDを行列へ分解したり `cell-${row}-${col}` を再生成したりすると、任意IDや採番を保持した編集後の
盤面で、数字を見落とす・塗りを無視する・正しい解答を誤りとする問題がある。
検証対象は問題レイヤーの数字と解答レイヤーの黒マスであり、頂点注記は正解の根拠にしない。
[共通ID契約](board-id-contract.md)に従い、IDの表記から意味を推測しない。

## 判定対象の解決

`rectangularBoard` は正方格子の実セルIDを、その時点の明示的な `index: [row, col]` と対応させる。
行列の一意性、4辺の実端点、頂点、隣接セルが論理的な正方格子として一致することを確認する。
境界辺配列と頂点配列の開始位置・向きが同じことは要求せず、辺の実端点を照合する。
行列はその検証中の検索キーであり、恒久IDや保存データの付け替えには使わない。

- 行列がない・重複する・接続が格子と一致しない・結合／分割等で対象が正方セルでない盤面は検証不能。
- 除外・盤外のセルは判定領域から外す。穴は視線と接続を遮る。余白を含むTopologyでは絶対行列を使う。
- 見た目の変形・回転は論理的な上下左右を変えない。座標の近さから別セルを選ばない。
- 数字や有効な黒マスの配置先が未解決なら検証不能。未解決の数字を飛ばして成功にしない。
- 非黒色の注記と、黒色でも `displayMode: dot` の注記は黒マスとして数えない。

旧Grid形式は、明示された参照モードに限り `gridUtils` の既知形式lookupを使う。
その行列は余白を除く問題領域が基準で、余白に負の行列がある。
Topologyに見つからないIDをGrid形式へ自動的に読み替えない。
ストアのCheck Answerは `useTopology` から参照モードを渡すため、保持中の頂点用Topologyがある
Grid形式の盤面でも、セル参照の体系を混同しない。

`runDataDrivenValidation` の第6引数は `'grid' | 'topology'`。
省略時は従来の呼出しと互換で、TopologyありならTopology、なしならGridとする。
直接checkerを使う場合も、任意の `ValidationContext.referenceMode` で参照体系を指定できる。

## ルールと検証不能

ぬりみさきの7ルールは同じ解決結果を使う。
黒マスの有無、黒／白の2×2、白マスの連結、数字から四方向に見える白マス数、
数字のあるセルが岬であること、数字のない白マスが岬でないことを調べる。
視線は数字自身を含み、黒マス・穴・盤外で止まる。連結と岬は実際の隣接関係を使う。
論理ルールは参照元の [pzprjs kurodoko.js](https://github.com/robx/pzprjs/blob/b783193307826514209173868f53ec56cdbe0eb4/src/variety/kurodoko.js) の
Nurimisakiチェックと照合した。

`CheckResult.unavailable` は、必要なデータを解決できず正誤を判定できないことを表す。
共通runnerは `complete: false`・`undecided: true` と `validation.unavailable` を返す。
これはパズルの数字が間違っているという結果とも、未登録checkerとも区別して実装する。
UIでは既存のUndecided表示と、確認できない検査がある旨の説明を使う。

黒マス必須と黒2×2はぬりみさき専用の登録名を使う。他ジャンル・カスタムchecklist向けの
共通名を上書きしない。従来の共通黒マス判定のGrid lookupと除外条件は互換動作として残す。
他ジャンルのID解釈除去まで完了したという意味ではない。

## 回帰防止と残り

固定の3×3解答は、白マスが上段・右端・下段をつなぎ、左上と左下の数字がともに3となる。
任意ID（区切り文字・空白・大小文字の違い・別種類に見える接頭辞を含む）で、全ルールが正解と判定する。
数字を99に変えると視線数の不一致を返し、Undo/Redo・保存再読込でも判定対象は同じセルである。
黒／白2×2、分断、岬、点注記、未解決参照・行列不明・非正方格子も検証する。
余白追加、Wave／Square、除外とGrid形式の余白も実ストアで確認する。

公開File Open・Check AnswerのChromium QAは、正解、数字99の誤答、行列欠損による検証不能、
ネイティブ再読込を同じ固定盤面で確認する。判定修正時の比較証跡は両revisionでジャンルを明示選択する。
その時点で見つかったMaster File Open/Saveの設定欠落は、後続の[設定保存修正](constraint-settings-persistence.md)で対応する。
判定の比較証跡と、プリセットの選び直しなしで読込を検証する後続QAは別に記録する。

LITS等の他ジャンル・共通判定補助にはIDを解釈する経路が残る。
非正方格子や意味を定義していない結合セルを、正方格子のぬりみさきとして推測で検査しない。
