# 大きい盤面の自動保存と容量超過

50×50盤面の実グラフ・2601個の頂点塗りをネイティブ形式で保持すると、
盤面設定の保存と未圧縮の自動保存がlocalStorageの容量を超える場合がある。
旧実装は2秒後の保存タイマーからQuotaExceededErrorを未処理で投げていた。
画面の編集やFile Saveが成功しても、自動保存が成功したことにはならない。

## 保存・復元の契約

`puzzlekit_autosave` と設定保存は、256 Ki文字を超えるJSONについてLZ-StringのUTF-16圧縮を試みる。
圧縮した封筒が元のJSONより小さいときだけ、その封筒を保存する。
識別子 `puzzle-kit-storage-json-lz-utf16-v1` と圧縮データを持つ内部保存形式であり、
ネイティブFile Saveや共有URLの形式は変えない。

盤面設定のグラフも同じ圧縮処理を使い、自動保存との容量競合を減らす。
圧縮はJSON文書全体へ適用し、ID・辞書キー・参照フィールドを置換しない。
従来の未圧縮JSONも引き続き読める。壊れた圧縮データは復元成功にしない。
圧縮形式を知らない旧アプリでの自動復元は保証しない。

保存は単一のsetItemで置き換え、失敗前に古い保存を削除しない。
容量を空けるために他の保存スロットやアプリのデータを削除することもない。
保存対象のグラフ・注記・制約設定は実行時の同じストア状態から取得する。
再試行も最後に失敗した古いオブジェクトではなく、現在の盤面を保存する。

## 失敗時の操作

MenuBarの自動保存は、容量超過・ストレージ利用不能などの例外を捕捉する。
保存失敗を非モーダルの通知で知らせ、ページを開いたままFile → Saveするよう案内する。
編集と手動保存は引き続き使える。Retryで即座に再試行でき、以後の編集でも保存を再試行する。
自動保存が成功した場合だけ通知を消す。手動保存の成功を自動保存の成功と混同しない。

容量が足りなければ、圧縮を使っても必ず保存できるとは限らない。
今回の対応はMenuBarの自動保存経路であり、設定保存・保存スロットの全失敗通知を統一するものではない。

## 回帰検証

既存の50×50公開画面テストに、自動保存の待機とページ再読込を追加した。
修正前はPC／Mobileで自動保存が作られず未処理例外を再現した。
修正後は編集済みの全注記とTopologyがページ再読込からも復元される。

容量超過のテストは隔離したブラウザの実localStorageを埋める。
setItemのモックや例外の無視は使わず、前回保存の維持、通知、手動保存、容量解放後の再試行、
ページ再読込による復元を確認する。
旧JSON読込と、大きい文書の圧縮・復元後も任意IDの辞書キーと参照が維持されることを実ストアでも確認する。
