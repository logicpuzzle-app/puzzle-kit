# 従来Grid三角盤面の列単位とID

従来Gridの描画・セル参照は1列あたり2三角形だったが、保存するTopologyは
1列あたり1三角形だった。そのため右半分の頂点に塗れず、参照モードの切替も失敗した。
列単位を明示し、保存済みのIDを保ったまま不足部分を補う。

## 列単位の契約

`GridConfig.triangleColumnUnit` は `cell`（1三角形）または `pair`（2三角形）。
新規作成・旧ファイル読込の境界で、省略値を明示した参照モードから補完する。
Topology形式の省略は `cell`、従来Grid形式の省略は `pair`。
IDの表記から形式や列数を推測しない。左右の周囲セル数は単位に関係なく三角形の個数である。

描画・ヒット判定・セルlookup・Topology生成・行列編集が同じ列単位を使う。
Grid／Topology切替では単位を維持し、画面上のセル数を変えない。
奇数個の三角形を持つTopologyからGridへ切り替える場合も、列数を丸めない。
セルlookupのキャッシュも列単位を区別する。

ネイティブ形式1.8.0の任意フィールドとして保存する。
設定・保存グラフ・除外前グラフ・結合／分割元グラフで値を一致させ、
不正値・不整合は読込を失敗させる。旧アプリでの再編集・再保存の互換性は保証しない。

## 旧スナップショットの補完

列単位のない従来Grid三角盤面について、保存済みの全グラフを規則的な旧半幅の配置と照合する。
適合する場合は共通の行列編集器で右側を追加する。セル・頂点・辺の保存済みIDと位置を維持し、
新しい要素だけに新IDを発行する。全幅の規則的なスナップショットも検証して受け入れる。
スナップショットがない旧ファイルは、明示した従来Gridの単位で全幅を生成する。

未知の変形・結合・分割・彫刻を含む旧グラフを、新しい規則盤面で置き換えない。
検証できなければ読込を失敗させ、現在の盤面・参照・履歴を保つ。
除外がある場合は保持した除外前グラフを補完し、宣言されたGrid参照で除外を再適用する。

## 注記・編集・履歴

Gridセルの数字等はGridの互換名前空間を使い、頂点塗りはGrid表示中もTopologyを参照する。
モード切替ではセル参照を検証した対応表で一体として移行し、頂点塗りの参照は維持する。
同じID文字列でも名前空間が違えば同一対象とはしない。

行列追加では存続IDを維持する。縮小では実際に消えたGridセルの注記とTopology頂点の塗りを、
それぞれの名前空間で整理する。削除前から未解決の参照を、形が似たIDというだけで削除しない。
両レイヤー・試行・Undo／Redo・ネイティブ保存を盤面と一緒に扱う。

## 検証と残る範囲

[実ストアテスト](../src/test/legacyTriangleIdentity.test.ts)で旧スナップショットの補完、
右側入力、上余白・列数変更、縮小、履歴・試行・保存、モード往復、不正読込の原子性を確認する。
[公開画面QAとハーネスQA](qa/2026-09-17-legacy-triangle.md)には画像・動画を残す。

三角Gridの頂点・辺には正方Gridと同じ互換参照体系は定義していない。
角・辺位置の数字など対応を検証できないデータを含む切替は拒否する。
従来Gridの矩形外枠・セル塗り・除外の描画をTopologyと統一する作業は残る。
これはセル中央の数字・Topology頂点塗りの参照と全幅を整合させる修正であり、
両モードの全機能や未知の構造編集が同等になったという宣言ではない。
