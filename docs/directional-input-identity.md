# 方向数字の入力先とジェスチャー

方向数字のマウス・タッチ・ペン入力は、開始時に解決したセルIDを保持する。
行列番号のない結合・分割セルも入力でき、同じ行列番号を持つ複数セルを同一視しない。
方向は対象セルの境界頂点と位置から既存の辺法線ルールで求める。IDの解析や再構築はしない。

- Arrow Numberのクリック／短いタップは同じセルで完了したときだけ数値を増やす。空セルは1から開始する。
- 数字のあるセルからセルサイズの0.3倍以上フリックすると、そのセルの数字の方向を変更する。空セルへ数字を作る操作ではない。
- 元から同じ向きでもフリックをクリックとして扱わず、数値を増やさない。
- 制約のDirection／対応するAutoモードも同じセル参照と方向処理を使う。クリック時の数字規則は各制約の既存処理を使う。
- Arrow Numberの右クリックはそのセルの方向数字を削除する。
- 方向変更中に数字・文字・色・オブジェクトキーを別セルへ移さない。盤面のセル・頂点・辺のIDは変更しない。

開始時の盤面・トポロジ・編集レイヤー・入力モード・表示変換を記録し、
途中で変更されたら保留中の入力を解除する。入力先が除外・削除された場合も適用しない。
同じIDのセルを含む文書を読み込み直した場合も、前の文書へのジェスチャーは再開しない。
マルチタッチへの切替、pointercancel、マウスの盤面外への退出で保留中の入力を解除する。

マウスの方向ジェスチャーは専用の履歴グループを持ち、タッチは既存のタッチ履歴グループに参加する。
一度のフリックで複数の方向へ動かしても、Undo一回で元の数字・方向へ戻す。
キャンセル時に既に適用済みの方向変更は履歴に残し、以後の移動やクリック入力を停止する。
グループの所有者だけが履歴を閉じる。ネイティブ保存では方向と実際のセルIDを保持する。

## 検証範囲

実ストアと入力ルーターのテストで、任意IDの盤面を分割してマウス／タッチ入力、
複数方向のフリックとUndo/Redo・保存復元、文書／レイヤー／トポロジ変更後の中断、
マルチタッチ・pointercancel、重複した行列情報、右クリック削除、制約のDirection／Autoを確認する。
公開UIのPlaywrightテストでは固定の分割済みファイルを開き、マウスとChromiumのタッチ入力で
7に右向きの矢印を付ける。隣の17と全セルのID・形状を保持し、Undo/Redo・保存再読込を比較する。

方向の幾何計算そのものを変更する機能ではない。複雑な凹形状での方向選択や
他の入力ツールに残るID解析は、この変更で対応済みとしない。
