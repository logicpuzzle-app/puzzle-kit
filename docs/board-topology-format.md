# ネイティブ盤面の保存形式（1.2）

[IDの契約](board-id-contract.md)に従い、Topologyモードの保存には、
画面で使用中の盤面を `topologySettings.topology` として含める。
盤面を保存時・読込時に生成し直して採番結果を合わせる方式には依存しない。

## データと復元

`topologySettings` は既存の `useTopology / topologyPreset / topologyIntensity` に
任意の `topology` を追加する。スナップショットは次を含む。

- `cells / vertices / edges`: `[id, record][]`。Mapのキー、各要素のID、
  位置、境界、隣接、index等をそのまま保持する。
- `bounds`: 描画範囲。
- `exclusionBase`: 任意の除外前の盤面。1段だけ保持し、非表示要素も同じIDで再表示できるよう保存する。
  [セル除外の仕様](board-cell-exclusion.md)を参照。
- `sourceConfig`: 生成元設定がある場合の補助情報。スナップショットの代わりにはしない。

読込時はスナップショットを優先する。IDの重複、Mapキーとrecord.idの不一致、
非有限の位置・範囲、存在しないセル・頂点・辺への接続は読込エラーにする。
この検査が失敗してもGrid設定から代替盤面を作らず、現在の盤面と履歴を変更しない。
セル・頂点・辺以外の全データについて新しい包括的検証器を追加したものではない。

スナップショットのない従来ファイルは、既存のGrid・プリセットから復元する。
従来の線の辺ID変換・重複線修復はこの経路で行う。
スナップショットのあるファイルの盤面参照は再割当てしない。
要素のレイヤー省略を復元する処理等、既存のデータ互換処理は維持する。

## 保存経路

ストアの `exportPuzzle / importPuzzle`、Fileメニュー、アイコンツールバー、
自動保存、共有用データ、ImportExportDialogのJSON出力で同じ形式を用いる。
設定の初期化は、先に読み込んだドキュメントの盤面を設定から再生成して上書きしない。
`useStoreIntegration` の保存・復元もスナップショットを引き継ぐ。

ストア以外の低レベルAPIで保存する呼出元は、`topologySettings.topology` を
渡す必要がある。Grid設定とパズル要素だけから使用中の盤面を復元することはできない。
`captureTopologySettings` は使用中の盤面と設定を一緒に取り出す内部ヘルパー。
従来Gridモードではスナップショットを必須とせず、既存のGrid形式の参照を保持する。

共有URLの新しい圧縮ペイロードは
`{ encoding: "puzzle-kit-json", data: PuzzleExport }` をzlib + URL-safe Base64で保存する。
旧形式のプロパティ名置換は読込互換としてだけ残す。
新規保存で置換をやめる理由は、`co` や `zL` といった要素IDもレコードのキーとして
そのまま保存するため。旧アプリで新しい共有形式を読めることは保証しない。

## 次の移行

この変更は保存・復元の基盤であり、[移行一覧](board-id-migration.md)の完了ではない。
除外・解除は保持した盤面からの投影に移行した。リサイズ・結合・分割・プリセット変更での
再生成や採番器の寿命管理は残っている。
保存した任意IDの盤面でも、これらの操作で同一性を守れるよう編集処理を変更する必要がある。
頂点塗り（#29）はその共通処理に接続する。位置やセルの角番号を永続IDの代用品にはしない。
