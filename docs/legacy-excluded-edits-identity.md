# 除外を伴う旧結合・旧分割の移行

旧保存データでは、除外後のグラフに採番した頂点・辺IDを分割線が参照する。
除外設定だけを外して盤面を生成し直すと、同じIDが別の点・辺を指し、分割が失敗する。
除外されたセルを結合設定からそのまま復活させると、保存時の構成員と境界まで変わる。
従来は元グラフと編集操作を復元できず、SplitのRestore cellを使えなかった。

## 保存された構成員と境界を維持する

旧生成器は除外の後で結合する。設定に `[A, B, C]` があっても、Aが除外されていれば
実際の結合セルの `originalCells` は `[B, C]` となる。この場合はBとCの結合として移行し、
Aの除外解除ではAを独立した元セルとして戻す。既存の結合セルへ自動的に追加しない。
結合し直す場合は明示的な編集とし、新しい結合セルへ新IDを発行する。

旧生成器が境界の角を省略した場合も、その保存済みの境界を保持する。
省略の結果、復元したセルと旧結合セルが一点でしか接しない場合は、結合をいったん解除して
元のセルをまとめ直す。読込時に近い点へ付け替えたり、境界を四角へ補正したりしない。
空になった設定上のグループは結合要素を作らず、後続グループのIDも詰め直さない。
すべてのグループが空の場合も、検証済みの元セルを復元し、実在しない結合設定を取り除く。
空の操作列や架空の結合元グラフを保存する必要はない。除外解除は元の各セルを戻し、
新しい結合は通常の操作として新IDを発行する。

グラフと正規化済みの設定は、`restoreBoard` の一つの結果として返す。
公開ファイル読込・ストアの読込・localStorageからの復元は、その同じ結果を一度に適用する。
操作列の有無だけを見て設定の正規化を飛ばすことはしない。
旧生成器との一致を証明できない盤面は、グラフと元の構造設定をそのまま保持する。

### 旧生成器が落とした盤外設定

旧結合・分割の生成器は、編集対象以外のセルも作り直し、`outboard` 属性を落としていた。
保存時の実セルが盤内である場合、残った `outboardCells` 設定を読み直して盤外へ変えると
隣接関係まで変わる。全グラフが旧生成器と一致すると確認した後に限り、その実セルに対する
未実現の盤外設定を取り除く。ID・形状・保存済みの盤内外属性・隣接関係は維持する。
見えていない元セルの設定はこの処理で推測して書き換えず、従来の編集時の参照整理に従う。
後から明示的に盤外へ変更することは可能で、解除・Undo/Redoも同じIDを対象とする。
独自グラフで対応を証明できなければ、元の設定も含めて変更しない。


## 読込時の対応

`prepareLegacyEditedExclusions` は、保存された可視グラフ全体が指定設定の旧生成器と
一致する場合だけ適用する。IDの接頭辞や末尾、行列番号を解析しない。

1. 除外後の元セル、分割前の実際の結合形状、分割後の形状と、除外前の元セルを取得する。
   無効化された結合出力を復元する際は、分割端点を元の親セル境界から明示的に対応させる。
   辺の向きが変わる場合は、辺途中の比率も反転する。
2. この検証済みの旧形式境界内でだけ、元座標と端点ペアからID対応表を作る。
   保存済みのIDを優先し、保存されていない頂点・辺には衝突しない新IDを発行する。
3. 元グラフへ旧結合の実際の境界、細分化された辺と分割端点を記録する。
   結合の構成員は実在した元セルだけを使う。子セル名は旧生成器の出力から取得する。
4. 元グラフと操作列を再生して除外を投影する。可視グラフの形状・ID・接続が旧出力と
   一致した場合だけ採用し、正規化した構造設定と一体で保存する。
   可視セル・頂点・辺の既存ID、座標、並び、注記の参照先は変更しない。

結合時に消滅した元の内部辺と、その位置に後から作られた分割線は別の要素である。
元の辺を復元しても、現在の分割線のIDを再発行しない。座標一致を恒久的な同一性として扱わない。
Wave等は旧盤面の変形基準を、隠れている点と元グラフにも適用する。
非表示点の復元で既存の点を動かさず、Squareへ戻すときは復元済みの点まで表示範囲に含める。
解除操作で消滅する子セルの数字などは従来の編集方針で除去し、Undoでグラフと注記を復元する。
単純な除外移行へ構造編集を渡して分割IDを再解釈するフォールバックは行わない。

## 検証範囲と残り

固定の旧保存fixtureは、結合の外の除外セルと、結合構成員の除外・角が省略された境界を扱う。
両者は共通のPlaywrightテストで、公開File OpenからPCマウス／ChromiumのPixel 7タッチ
エミュレーションを使い、読込直後の全ID・形状、分割解除、Undo/Redo、保存再読込を比較する。

実ストアのUnitは、除外された元セルの独立した復元、元セルを明示的に結合し直した際の新ID、
途中の空グループによる再採番の防止、元の内部辺と分割線のIDの分離も検証する。
Waveの再適用とSquare復帰・レイアウト変更、結合セル全体の旧無効化、未知のグラフの保全も扱う。
全グループが空の固定fixtureでは、除外解除・新しい結合・Undo/Redo・保存再読込を検証し、
localStorageの基本設定が古くても保存グラフの設定から一体で復元されることを確認する。

離れた構成員・穴がある旧結合も、保存境界が一つの元境界ループとして検証できる場合は復元できる。
境界が分岐する等、保存境界と元グラフの操作を検証できない旧盤面は未移行である。
余白を含む旧結合は[元セルと出力セルの役割を分けて復元](legacy-merge-identity.md)する。
結合を経ない余白セルの旧分割も[元セルと子の役割を分けて復元](legacy-split-identity.md)する。
彫刻、由来不明の独自グラフ、既に別方式で保存された不完全な除外元グラフは別途対応が必要。
不明な対応を推測せず元の保存グラフを保持する。これらを解決済みとは扱わず、PR #126はDraftを維持する。
